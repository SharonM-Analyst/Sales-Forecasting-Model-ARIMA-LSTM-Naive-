# Sales Forecasting — LSTM (2017)
## Time Series: NEURAL NETWORK(LSTM), ARIMA, SARIMAX, NAIVE BASELINE
## Structure

```
input/
    Sales_Processed.csv       <- put the raw source file here (not included)
    train.csv                 <- generated by create_folds.py (train+valid rows)
    test.csv                  <- generated by create_folds.py (holdout period)
src/
    config.py                 <- every path/hyperparameter, in one place
    create_folds.py           <- raw CSV -> calendar features -> chronological split
    models.py                 <- LSTM architecture + sequence-windowing helper
    model_dispatcher.py       <- model-name -> builder, plus naive/ARIMA/SARIMAX baselines
    train.py                  <- fit, validate, compare to baselines, save model+scalers
    inference.py              <- full-history refit + recursive 2017 forecast
models/
    (created by train.py / inference.py: model_lstm.keras, scalers, best_epoch.bin, ...)
notebooks/
    check_data.ipynb         <- data-quality gate, run before create_folds.py
    exploration.ipynb        <- open-ended EDA + results review, no pipeline dependency
output/
    (created by inference.py: daily/monthly 2017 forecast CSVs)
```

## Why it's split this way

The original notebook did everything top to bottom in one file —
useful for exploring, awkward for reusing. Each script now has one
job, and `config.py` is the only place that knows about file paths
or hyperparameters, so nothing is hard-coded twice.

## Run order

```bash
# 1. Drop the raw file at input/Sales_Processed.csv, then sanity-check it
jupyter notebook notebooks/check_data.ipynb

# 2. Build features + chronological train/valid/test split
python src/create_folds.py

# 3. Train the LSTM, evaluate against baselines, save model + scalers
python src/train.py --model lstm

# 4. Refit on full history and generate the 2017 daily/monthly forecast
python src/inference.py

# 5. (optional) dig into results
jupyter notebook notebooks/exploration.ipynb
```

## Notebook split, clarified

- **`check_data.ipynb`** — a gate, not an analysis. Load the raw CSV,
  check for missing values, duplicate or non-daily dates, and glance
  at the raw series. If this notebook doesn't run clean, fix the
  source data before anything downstream touches it.
- **`exploration.ipynb`** — everything open-ended: distribution/
  skewness checks, sanity-checking the engineered calendar features,
  and (once `train.py`/`inference.py` have run) reviewing the model
  comparison and the 2017 forecast. Nothing here produces a file the
  pipeline depends on — it's for looking, not for building.
